Project Overview

What I Built

An end-to-end analytics pipeline that ingests raw job postings from multiple sources, engineers structured intelligence through NLP, stores results in PostgreSQL, and produces analytical outputs for Power BI and Python visualization.

⚙

Data Engineering

Multi-source ingestion, validation, deduplication, and cleaning of 8,256 job postings from Adzuna UK and CHISEL/LUMS Pakistan.

🔍

NLP & Skill Extraction

Lexicon-based skill extraction with contextual disambiguation, reducing false positives by 75% through pattern analysis and validation.

📊

Analytics & BI

13 SQL analytical views, Python statistical analysis, and a 10-page Power BI dashboard specification for workforce intelligence.

Business Problem

Why This Matters

Job postings contain fragmented information about skills, salaries, roles, seniority, locations, and work modes. Raw postings are difficult to compare directly across sources, companies, and countries.

The Problem

Workforce data is scattered across job boards, each with different formats, taxonomies, and coverage. A data analyst targeting the UK market needs structured intelligence, not raw postings.

The Solution

This platform transforms raw, unstructured job postings into a normalized analytical model: skills extracted via NLP, roles classified, salaries standardized, and market patterns surfaced through SQL and statistical analysis.

NLP Engineering

Skill Extraction & Remediation

The NLP layer extracts, normalizes, and validates skills from unstructured job descriptions using a lexicon of 78 canonical skills with contextual disambiguation.

How It Works

Lexicon matching: 78 skills with 200+ aliases mapped to canonical names.
Word boundaries: Prevents false matches (e.g., "R" in "SQL" or "senior").
Contextual rules: Positive/negative context patterns disambiguate skills like R, Go, Scala, SAS, C#.
Provenance: Each extraction records confidence, source field, and extraction method.

Results

Before remediation: 28,972 total skill mentions (many false positives).
After remediation: 7,256 validated skill mentions.
False positive reduction: 75% of invalid matches eliminated.
Validation: 25 dedicated false-positive prevention tests confirm accuracy.

Why This Matters

This was not achieved by simply deleting frequent skills. The system identified ambiguous pattern matches (e.g., "R" appearing in "SQL", "senior", "data") and applied contextual rules with positive and negative context patterns. Each extraction carries provenance metadata including confidence level, source field, and extraction method.

Key Findings

What the Data Shows

Evidence-based findings from the analytical layer. Each finding is supported by the validated Phase 5 outputs.

Market

UK Data Roles Are Well-Structured

46.5% of UK postings are classified as Data Analyst, Data Scientist, or Analytics Engineer. The remaining 48% are “other” roles that require data-adjacent skills.

Skills

UK and PK Skill Profiles Are Fundamentally Different

UK emphasizes reporting, ML, and BI tools. Pakistan emphasizes PHP, communication, and web technologies. The gap reflects both different market structures and different dataset periods.

London

London Dominates UK Data Roles

76.3% of UK postings are in London. Greater London adds another 16.9%. Only 6.7% of UK data roles are outside the London cluster.

Salary

UK Median Data Salary: £63,394

99.6% of UK postings include salary data. The median advertised salary across all data roles is £63,394. Statistical tests show no significant salary difference between senior and junior roles (Mann-Whitney U, p=0.07).

Career

SQL and Python Are Universal Requirements

SQL and Python appear across all three target roles (Data Analyst, Analytics Engineer, Data Scientist). They are the baseline technical skills for UK data careers.

Quality

NLP False Positives Were Systematic

Without remediation, the skill extractor would have reported 28,972 skill mentions. Contextual disambiguation reduced this to 7,256 validated mentions — a 75% reduction in invalid data.

PostgreSQL Analytical Model

NLP with Provenance

Every skill extraction records: confidence level (high/medium/low), source field (title/description), extraction method (lexicon/contextual), and context window. Enables downstream quality filtering.

Statistical Validation

Chi-square test confirms skill distribution differs significantly between UK and PK (p≈0). Mann-Whitney U test on salary by seniority shows no significant difference (p=0.07). All tests documented with limitations.

Transparency

Limitations

Analytical credibility requires acknowledging what the data cannot tell us.

  • UK and Pakistan datasets are not temporally equivalent. UK data is recent (2023–2026); Pakistan data is historical (2019–2024). Direct comparison reflects dataset period, not necessarily current market conditions.
  • Job postings represent employer demand, not the complete labor market. Self-employed, internal hires, and word-of-mouth placements are underrepresented.
  • The CHISEL/LUMS Pakistan dataset classifies 99% of roles as “other” due to its original taxonomy, limiting role-specific analysis for Pakistan.
  • Salary analysis is UK-only. The Pakistan dataset does not contain comparable salary information.
  • Skill extraction is limited to 78 canonical skills. Domain-specific or emerging skills not in the lexicon are not captured.
  • London concentration (76%) reflects Adzuna’s UK coverage, not necessarily the entire UK data labor market.
  • Sample sizes for some breakdowns (e.g., Analytics Engineer salary by seniority) are small and should be interpreted cautiously.
